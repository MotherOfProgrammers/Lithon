01The mental model

Lithon behaves like a two-lane road. Proven, static operations take the Tier-1 native path. Dynamic or unhandled operations fall back to a Tier-0 C++ interpreter instead of pretending uncertainty is free.

Read like Python

Familiar syntax and explicit annotations keep the surface expressive.

Prove before run

The verifier rejects type flow it cannot mathematically establish.

Emit native

Typed AST blocks become guard-free x86-64 instructions.

02Types & flow

Every variable needs a fixed type before execution begins. That constraint is not ceremony—it is the contract that lets Lithon avoid boxing, dynamic dispatch, and hot-path checks.

examples/fib.py
def fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

03Runtime notes

The native backend allocates executable memory through the operating system and writes machine code directly. The engine is designed to stay small: no LLVM, no Cranelift, no external runtime stack.
