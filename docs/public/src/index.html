03 / Quickstart

From clone
to run.

Three commands. Zero dependency hunting. The fastest way to see Lithon’s promise for yourself.

Read the full README ↗
terminal
$ git clone https://github.com/MotherOfProgrammers/Lithon.git
$ cd Lithon
$ cmake -B build -DCMAKE_BUILD_TYPE=Release
$ cmake --build build -j$(nproc)
$ python3 src/frontend/frontend.py tests/programs/float.py > /tmp/float.ir
$ ./build/tier_runner /tmp/float.ir --strict

04 / The themes

Four convictions
behind the engine.

Lithon is not a bag of features. It is four convictions about what a language owes the person writing the code — and every layer of the engine exists to serve one of them.

01Ownership

Nothing
to inherit.

llvm✗
cranelift✗
runtime libraries✗
first principles✓

No compiler toolkit underneath, no package graph behind the language. Every layer is small enough to read in one sitting, which is the only way an engine can stay fast and stay understood at the same time.

02Proof

Nothing
left to chance.

flow analysisstatic
guards emitted0
runtime dispatchnone

Types are settled before the code runs. Once a program is verified, the hot path carries no guards and no dynamic lookups — the machine executes exactly what the verifier promised it would.

03Proximity

Closer than
a code review.

frontendPython
engineC++20
outputx86-64

The distance between an idea and the instruction that runs it is three deliberate layers. No abstraction tax, and no intermediate representation that nobody owns.

04Openness

Open
by default.

licenseMIT
issueswelcome
roadmappublic

The engine, the verifier, and the roadmap sit in public from the first commit. Read it, disagree with it, and open the pull request — the roadmap here is a conversation, not a surprise.
